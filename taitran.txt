# Ansible deploy to Ubuntu

## Store Tailscale and database credentials in Ansible Vault

From the `ansible` directory, create or edit the encrypted variables file:

```bash
cd ~/Developer/test/ontap/ansible
ansible-vault edit inventory/group_vars/all/vault.yml
```

Keep these variables in the Vault file. Enter their real values locally; never put them in this note or commit them:

```yaml
tailscale_auth_key: 'PASTE_THE_FULL_TAILSCALE_AUTH_KEY_LOCALLY'
app_db_password: 'PASTE_A_NEW_MYSQL_PASSWORD_LOCALLY'
```

The Tailscale value must be the complete Auth key copied from the correct tailnet. Do not use OAuth client credentials or manually add a prefix.

## Run provisioning and deployment

```bash
cd ~/Developer/test/ontap/ansible
ansible-playbook playbooks/deploy.yml --ask-become-pass --ask-vault-pass \
  -e app_repo_url=https://github.com/taitran05072006/ontap.git \
  -e ansible_ssh_private_key_file="$HOME/.ssh/ubuntunew"
```

The inventory deploys the two-node layout:

- `192.168.64.4`: host Nginx load balancer, backend 1, frontend and MySQL
- `192.168.64.7`: backend 2

The Nginx configuration is maintained on the Mac at
`ansible/roles/deploy/templates/nginx.ontap.j2`. Ansible copies it to
`/etc/nginx/sites-available/ontap`, enables the site, and reloads Nginx.
Backend traffic is load-balanced through the `ontap_backend` upstream.

For CI/CD, configure `ANSIBLE_VAULT_PASSWORD` and `APP_DB_PASSWORD` in
GitHub Actions secrets in addition to the Docker Hub and SSH secrets. The
workflow runs the same Ansible deployment against both Ubuntu machines using
the image tag for the commit SHA.
